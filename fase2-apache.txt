2. PREGUNTAS PARA DISCUTIR


Pregunta 1. ¿Qué muestra la página por defecto de Apache?
Respuesta:
Muestra la página "Apache2 Ubuntu Default Page: It works!". Confirma que
Apache se instaló correctamente y está atendiendo peticiones HTTP en el
puerto 80. La página explica la estructura de configuración de Apache en
Ubuntu (apache2.conf, ports.conf y los directorios mods-enabled, conf-enabled
y sites-enabled) y que el DocumentRoot por defecto es /var/www/html, donde
está el archivo index.html que debe reemplazarse antes de poner el sitio en
producción.
Evidencia: capturas/fase2-apache-activo.png (tomada en nuestro entorno).

Pregunta 2. ¿Qué diferencia hay entre sites-available y sites-enabled?
Respuesta:
- /etc/apache2/sites-available/ guarda todos los archivos de configuración
  de Virtual Hosts disponibles, estén activos o no. En nuestro servidor
  contiene 000-default.conf y default-ssl.conf.
- /etc/apache2/sites-enabled/ contiene únicamente enlaces simbólicos a los
  sitios que están activos. Apache solo lee esta carpeta al arrancar.
- El comando a2ensite crea el enlace simbólico (activa el sitio) y a2dissite
  lo elimina (desactiva el sitio) sin borrar el archivo original. Así se
  puede activar o desactivar un sitio sin perder su configuración.

Pregunta 3. Ejecuten sudo apache2ctl configtest. ¿Qué reporta? ¿Por qué es
importante antes de reiniciar?
Resultado obtenido: Syntax OK
Respuesta:
Reporta "Syntax OK", lo que significa que la sintaxis de todos los archivos
de configuración es válida. Es importante ejecutarlo antes de reiniciar o
recargar porque, si hubiera un error y se reiniciara directamente, Apache no
arrancaría y el sitio quedaría caído. Con configtest el error se detecta
mientras el servicio anterior sigue funcionando y se puede corregir sin
interrumpir el servicio.

Pregunta 4 (Reto). Si Apache no arrancara, ¿qué 3 pasos seguirían para
diagnosticar el problema?
Respuesta:
1) Revisar el estado del servicio y su mensaje de error:
   sudo systemctl status apache2
   journalctl -xeu apache2
2) Validar la configuración y revisar los registros:
   sudo apache2ctl configtest
   sudo tail -n 50 /var/log/apache2/error.log
3) Verificar conflictos de puerto y módulos:
   sudo ss -tlnp | grep :80
   Si otro servicio (por ejemplo IIS en Windows) usa el puerto 80, se
   detiene o se cambia el puerto en /etc/apache2/ports.conf. También se
   confirman los módulos cargados con apache2ctl -M.


3. ERRORES ENCONTRADOS Y CÓMO SE RESOLVIERON


Error 1: WslRegisterDistribution failed with error: 0x800701bc
  Mensaje: "WSL 2 requiere una actualización de su componente de kernel."
  Causa: el kernel de WSL2 en Windows estaba desactualizado.
  Solución: se actualizó WSL desde PowerShell como administrador con
            "wsl --update" y luego "wsl --shutdown".

Error 2: WslRegisterDistribution failed with error: 0x80370114
  Mensaje: "No se pudo iniciar la operación porque no se instaló una
           característica requerida."
  Causa: faltaba una característica de Windows necesaria para WSL2 o la
         virtualización no estaba disponible/activada.
  Solución: [COMPLETAR con lo que realmente hizo: por ejemplo, activar las
            características "Subsistema de Windows para Linux" y
            "Plataforma de máquina virtual" con dism, reiniciar la PC y/o
            activar la virtualización en la BIOS].

Resultado: Ubuntu se instaló y funciona correctamente en WSL2.
